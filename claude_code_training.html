Claude Code 與 CCR 內部環境導入指南

專為韌體(FW)與通訊團隊打造的安全離線輔助工具

操作說明：請使用鍵盤的 ← 與 → 鍵，或右下角按鈕進行切換

什麼是 Claude Code？(破除 AI 迷思)

不需要懂 LLM 或 Agent 這些艱澀名詞，您可以把它視為系統工程中的一個：

  • 不知疲倦的初階工程師：它沒有硬體直覺，但能夠在一秒內閱讀並交叉比對幾千頁的 PDF 規格書。
  • 終端機裡的整合腳本：它直接安裝在您的 Command Line 裡，不用切換視窗去開網頁，直接與您的 C/C++ 原始碼放在同一個資料夾。
  • 遺留程式碼翻譯機：專門用來幫您解釋十年前離職學長寫的、完全沒有註解的複雜位元運算與指標操作。

安全離線安裝與 CCR (路由中介層)

公司的資安規範嚴禁程式碼上傳至雲端。因此 IT 部門準備了 CCR (Claude Code Router) 來解決這個問題。

  • CCR 就像內部的郵局： 它會自動攔截發送出去的網路封包，安全地導向公司內部的私有 AI 伺服器，確保機密不外流。
  • 安裝與啟動超簡單（關鍵：需要開啟兩個終端機視窗）：

終端機 1 (擔任背景引擎，請勿關閉)

# 啟動內部路由引擎
ccr start

終端機 2 (您的開發駕駛座)

# 載入環境變數並啟動工具
eval "$(ccr activate)"
claude

最常用的基礎指令矩陣

終端機指令 / 斜線指令 韌體開發實務應用情境
claude "問題描述" 開啟互動介面並直接帶入任務。例如：
claude "請分析 main.c 的中斷設定"
claude -c 延續上一次還沒做完的討論，不用從頭解釋專案背景，適合中斷恢復。
cat error.log | claude -p 利用管道 (Pipe) 處理大量 Log，找尋編譯或連結器報錯的根本原因。
/clear (在介面內輸入) 極度重要：清除對話記憶。當工具開始將不同 MCU 的暫存器位址搞混時，立刻使用此指令重置狀態。

對韌體 (FW) 開發真正有幫助的情境

🔥 情境一：硬體規格書 (Datasheet) 處理

把 MCU 的 PDF 規格書轉成純文字 (.md) 放在專案內，請它自動提取 SPI/I2C 暫存器的位址並轉成 C 語言 Struct。再也不會因為人工算錯 Bit Offset 而除錯一整天。

🔥 情境二：中斷服務常式 (ISR) 效能健檢

ISR 必須極度簡短。您可以請它審查程式碼中是否隱藏了浮點運算、耗時的 Blocking Calls，或建議如何改用 DMA 傳輸來降低 CPU 負載。

高階心法與避坑指南

  • 加上嚴格的硬體約束條件： 不要只要求「寫一個 Buffer」，要明確下達指令：「寫一個 Ring Buffer，禁止使用 malloc，且大小必須是 2 的冪次方，確保 Thread-safe。」
  • 規劃優先於執行： 遇到需要修改多個檔案的需求，先要求它列出「影響性分析與修改計畫」。您檢查計畫確認無誤後，再授權它改 Code，避免專案崩潰。
  • 建立「記錄並清除」的習慣： 聊太久系統會邏輯發散。完成一個小任務後，請它把進度寫入 status.md，然後輸入 /clear 清除記憶，再請它讀取該檔案重新開始。
